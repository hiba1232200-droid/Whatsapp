# 🏆 بوت لوحة ترتيب الإضافات — WhatsApp Group Adds Leaderboard

بوت واتساب مبني على **Node.js + Baileys** يبني لوحة ترتيب لأكثر أعضاء المجموعة إضافةً للأشخاص الجدد، ويحفظ الأعداد في قاعدة **SQLite** لتبقى بعد إعادة التشغيل.

---

## ✅ هل الميزة مدعومة تقنياً؟ (فحص أولي)

**نعم، مدعومة.** إصدارات Baileys الحديثة تُطلق حدث `group-participants.update` ويحتوي على حقل **`author`** الذي يخبرنا **مَن نفّذ الإجراء** (مَن أضاف العضو)، بالإضافة إلى `authorPn` (رقم الهاتف عند توفره):

```ts
'group-participants.update': {
  id: string            // معرّف المجموعة
  author: string        // مَن قام بالإجراء (قد يكون @lid أو @s.whatsapp.net)
  authorPn?: string     // رقم هاتف المنفِّذ (إن توفّر)
  participants: [...]   // الأعضاء المتأثرون
  action: 'add' | 'remove' | 'promote' | 'demote'
}
```

عند `action === 'add'` نعرف مَن أضاف (`author`) ومَن أُضيف (`participants`)، وهذا كافٍ لبناء اللوحة بدقة.

### قيود حقيقية تعامَل معها الكود (بلا تخمين)

1. **الانضمام عبر رابط الدعوة:** عندما ينضم شخص بنفسه عبر الرابط، يظهر الحدث كـ `add` لكن `author` يساوي نفس الشخص المُضاف. لا يوجد "مضيف" حقيقي هنا، لذا **لا نحتسبه افتراضياً** (يمكنك تغيير ذلك عبر `countInviteLinkJoins` في `config.js`).
2. **غياب `author`:** في حالات نادرة قد لا يصل المنفِّذ. القاعدة صارمة: **إن لم نعرف مَن أضاف، لا نُخمّن ولا نحتسب** — نتجاهل الحدث بصمت.
3. **تحوّل الهوية من رقم هاتف إلى LID:** واتساب صار يخفي أرقام الهواتف داخل المجموعات مستخدماً معرّف `@lid`. الكود يفضّل رقم الهاتف (`authorPn`) كمعرّف ثابت عند توفره، ويستخدم `author` كبديل، حتى يبقى ترتيب العضو ثابتاً.
4. **البوت يعدّ من لحظة تشغيله فقط:** لا توجد طريقة لمعرفة مَن أضاف الأعضاء *قبل* دخول البوت المجموعة. العدّ يبدأ من الآن فصاعداً.

> ملاحظة مهمة: يجب أن يكون حساب البوت **عضواً في المجموعة وموجوداً وقت الإضافة** حتى يستقبل الحدث. لا يلزم أن يكون مشرفاً لاستقبال الأحداث، لكن كونه مشرفاً يجعل الاستقبال أكثر موثوقية.

## 📦 المتطلبات

- Node.js نسخة 20 أو أحدث
- رقم واتساب مخصّص للبوت (يُفضّل رقم مستقل)
- أدوات بناء لمكتبة `better-sqlite3` (تُثبّت تلقائياً؛ على لينكس قد تحتاج `build-essential` و`python3`)

## 🚀 التثبيت والتشغيل

```bash
# 1) فك الضغط ثم ادخل المجلد
cd wa-adds-bot

# 2) ثبّت الاعتماديات
npm install

# 3) شغّل البوت
npm start
```

عند أول تشغيل سيظهر **رمز QR** في الطرفية. افتح واتساب على هاتف البوت:
**الإعدادات ← الأجهزة المرتبطة ← ربط جهاز** ثم امسح الرمز.

بعد الربط، تُحفظ الجلسة في مجلد `auth/` ولن تحتاج لإعادة المسح في كل مرة.

ثم **أضف رقم البوت إلى مجموعتك**. من تلك اللحظة يبدأ العدّ.

---

## 🕹️ الأوامر

تُكتب داخل المجموعة:

| الأمر | الوظيفة |
|------|---------|
| `!top` | يعرض أكثر 10 أعضاء إضافةً (قابل للتعديل عبر `topLimit`) |
| `!mystats` | يعرض عدد الأشخاص الذين أضفتهم وترتيبك |
| `!help` | عرض قائمة الأوامر |

---

## ⚙️ الإعدادات (`src/config.js`)

- `prefix` — بادئة الأوامر (الافتراضي `!`).
- `allowedGroups` — ضع معرّفات مجموعات محددة لقصر عمل البوت عليها، أو اتركها `[]` ليعمل في كل المجموعات.
- `topLimit` — عدد الأعضاء في `!top`.
- `countInviteLinkJoins` — هل نحتسب من انضم عبر الرابط؟ (`false` موصى به).

## ☁️ النشر على Railway

نظام ملفات Railway **مؤقّت**، لذا بدون Volume ستُمسح جلسة الدخول والإحصائيات مع كل إعادة نشر. اتبع الخطوات:

**1) ارفع المشروع**
ارفعه إلى مستودع GitHub، ثم في Railway: `New Project ← Deploy from GitHub repo`. سيكتشف Nixpacks المشروع تلقائياً (ملفّا `railway.json` و`nixpacks.toml` مضمّنان).

**2) أضِف Volume ثابت (الأهم)**
من إعدادات الخدمة: `Volumes ← Add Volume`، وحدّد مسار التركيب مثلاً `/data`. هذا يحفظ مجلد `auth/` وقاعدة `data/stats.db` بين عمليات النشر.

**3) أضِف المتغيّرات (`Variables`)**

| المتغيّر | القيمة | ملاحظة |
|---------|--------|--------|
| `DATA_DIR` | `/data` | نفس مسار الـ Volume — إلزامي للحفظ الدائم |
| `PAIRING_NUMBER` | `9639XXXXXXXX` | رقم البوت للربط برمز اقتران (بدون + و00). فارغ = استخدام QR |
| `PREFIX` | `!` | اختياري |
| `TOP_LIMIT` | `10` | اختياري |
| `ALLOWED_GROUPS` | `...@g.us,...` | اختياري لقصر البوت على مجموعات محددة |
| `COUNT_INVITE_JOINS` | `false` | اختياري |

**4) اربط الحساب من السجلّات (`Deploy Logs`)**
- إذا وضعت `PAIRING_NUMBER`: سيظهر **رمز من 8 خانات** في السجلّات. افتح واتساب على هاتف البوت ← الأجهزة المرتبطة ← *الربط برقم الهاتف بدلاً من ذلك* ← أدخل الرمز.
- إذا تركته فارغاً: سيُطبع **رمز QR** في السجلّات لتمسحه بالكاميرا.

**5) أضِف رقم البوت إلى مجموعتك** ويبدأ العدّ. بعد الربط تبقى الجلسة محفوظة على الـ Volume ولن تحتاج لإعادتها.

> تلميح: `PAIRING_NUMBER` هو الخيار الأنسب على Railway لأن مسح QR من داخل عارض السجلّات صعب أحياناً.

### باختصار — شو بدك تضيف على Railway؟

1. **Volume** مركّب على `/data`.
2. متغيّر **`DATA_DIR=/data`**.
3. متغيّر **`PAIRING_NUMBER`** برقم البوت (أو اتركه فارغاً لـ QR).
باقي الملفات (`railway.json`, `nixpacks.toml`, `.env.example`) جاهزة داخل المشروع.

## 🧩 استكشاف الأخطاء

- **فشل بناء `better-sqlite3`:** ثبّت أدوات البناء: على أوبنتو `sudo apt install -y build-essential python3`.
- **لا يظهر QR:** تأكد أن الطرفية تدعم عرضه، أو احذف مجلد `auth/` وأعد التشغيل.
- **`!top` فارغ:** طبيعي في البداية — العدّ يبدأ بعد أول عملية إضافة يشهدها البوت.
- **تسجيل خروج متكرر:** احذف مجلد `auth/` وأعد ربط الجهاز.
